# TwinBuddy 懂你行动卡 — 组件设计稿

> 依据：PLAN.md v2 + PM 评审（4 态卡片 + 1 关键瞬间 + 三段结构化协商 + 降权/抑制）
> 目标：PRD §5.2 全部 10 项齐全，PRD §18 四种状态都支持
> 拒绝：聊天记录转录、品牌自指句（"路线可以按 TwinBuddy 这版走"）

---

## 1. ActionCard 通用组件

### 1.1 状态机

```
[hint]     轻提示卡：刚识别到兴趣，但意图不强
  ↓ 用户点 "帮我看看"
[plan]     行动方案卡：已生成完整方案
  ↓ 用户点 "看搭子"
[buddy]    搭子协商卡：3 个候选 + 协商结果
  ↓ 用户选一个
[complete] 推进完成卡：已生成邀约文案
```

每个状态可独立展示，不需要进入完整状态机。

### 1.2 Props（与 docs/action-cards.md §8 数据契约对齐）

```ts
interface ActionCardProps {
  data: ActionCard                            // 见 docs/action-cards.md
  variant: 'hint' | 'plan' | 'buddy' | 'complete'  // 强制状态
  expandLevel: 0 | 1 | 2                       // 折叠 / 半展开 / 完整
  onAction: (action: NextAction) => void
  onDampen: (scene: SceneType) => void         // "抑制此类"
  onClose: () => void
}
```

### 1.3 视觉规范

- **背景**：深色（黑/深蓝），与 Feed 普通视频区分（不能"长得像视频"）
- **位置**：占满 80-90% 屏幕（**比视频大**），与 PRD §9 一致
- **顶部角标**：场景 icon（旅行/美食/...）+ Twin 成熟度（轻量圆点）
- **截止时间**：右上角小字（如"还剩 2 个名额"）
- **不出现**：抖音 logo / 抖音水印 / 任何"刷一刷就有"的暗示

### 1.4 4 态结构

#### `[hint]` 轻提示卡
- 标题：20-25 字，疑问/确认语气
- 触发原因：1 句话，引用用户最近 1-2 个行为
- 按钮：`帮我看看` / `暂时不用` / `不再推这类`

#### `[plan]` 行动方案卡
- 标题：22-30 字
- 触发原因：2 句话（行为 + 场景）
- 行动方案：时间 + 地点 + 预算 + 路线（列表）
- 信任锚：距离 / 排队时间 / 营业时间（≥ 1 个）
- 按钮：`查看方案` / `换一个` / `收藏` / `看搭子` / `抑制`

#### `[buddy]` 搭子协商卡
- 标题 + 触发原因（沿用 plan 态）
- 3 个候选：横排卡片，A/B/C
- "**AI 协商关键瞬间**"：1 句话（见 §2）
- 三段结构化（见 §2）
- 按钮：`选 A/B/C` / `只要计划不要人` / `换一个人` / `抑制`

#### `[complete]` 推进完成卡
- 邀约文案：≤ 60 字，**真人语气**（见 §3）
- 4-5 个承接按钮（路线/团购/票务/收藏）
- 按钮：`发送邀约` / `换个语气` / `再协商一轮` / `换一个搭子`

## 2. AI 分身协商页（F3 — 评审最关心）

### 2.1 设计稿（评审要的"1 关键瞬间 + 三段结构化"）

```
┌──────────────────────────────────────┐
│  ← 你的 Twin 和 A 的 Twin 聊过 3 轮 │
│                                      │
│  关键瞬间                            │
│  ┌────────────────────────────────┐ │
│  │ A: "你接受临时改时间吗？"      │ │
│  │ 你: "只在早上不接受。"         │ │
│  │ — 冲突被识别并协商 ✓           │ │
│  └────────────────────────────────┘ │
│                                      │
│  已达成共识                          │
│  ✓ 时间都接受周六 14:00 后          │
│  ✓ 预算都希望 200 元以内            │
│  ✓ 都不特种兵                       │
│  ✓ 首次见面地铁口见                 │
│                                      │
│  待确认                              │
│  · 对方希望多拍照，你偏散步         │
│  · 返程时间需对齐                   │
│                                      │
│  风险提示                            │
│  ⚠ 对方偏早起（建议再约 14:30）    │
│  ⚠ 周末大鹏交通可能堵              │
│                                      │
│  推荐推进程度：79%                   │
│                                      │
│  [选 A]  [只要计划]  [换 B]         │
└──────────────────────────────────────┘
```

### 2.2 关键设计要点

- **关键瞬间**（"1 个最关键的协商回合"）：不是聊天流，是**一个最有信息量的回合**——展示 AI 识别的冲突 + 解决方式
- **已达成共识**：4 项以内（多了就是堆数据）
- **待确认**：1-3 项（必须有，否则会显得"AI 决定一切"）
- **风险提示**：用 ⚠ icon，不用文字 block
- **推进程度**：0-100%，**永远 < 100%**（=100% = AI 替用户做决定，反 PRD §16）

### 2.3 拒绝的反模式

❌ **反模式 A**：堆 5 行 "已达成共识"，看起来像 mock 数据
❌ **反模式 B**：硬塞 3 轮完整对话流，看起来像 toy
❌ **反模式 C**：用 ✗ 标记对方"不"，显得 AI 在评判
❌ **反模式 D**：用 ❌ 标"未达成"，显得 AI 替用户拒绝了

✅ **正解**：1 个关键瞬间（最有信息量） + 三段（短而具体） + 推进程度 < 100%

### 2.4 数据契约

```ts
interface NegotiationSummary {
  agreed: string[]                // 已达成共识（≤ 4 项）
  pending: string[]               // 待确认（1-3 项）
  risks: string[]                 // 风险（1-2 项）
  key_moment: KeyMoment           // PM 评审要的"1 个关键瞬间"
  progress: number                // 0-100，**永远 < 100**
}

interface KeyMoment {
  speaker: 'user_twin' | 'buddy_twin' | 'system'
  text: string
  detected_conflict: string       // 冲突是什么
  resolution: string               // 怎么被协商
  outcome: 'agreed' | 'pending' | 'escalated'  // 永远只能是这三个
}
```

## 3. 一键邀约文案（F4 — 评审要的"真人语气"）

### 3.1 反文案范例

❌ "我也想周六下午去大鹏轻松逛逛，看到我们预算和节奏挺一致，要不要先约 14:00 在地铁站见，路线可以按 TwinBuddy 这版走？"

问题：
- "路线可以按 TwinBuddy 这版走"是**品牌自指**
- 整句太"AI 范"
- 缺信任锚 + 缺截止感

✅ **改写范例**：
> "我周六下午也想去大鹏吹吹风，你那边刚好顺路吗？预算 180 我俩 AA 还行，到时微信约时间？"

- 去掉了品牌自指
- 用了"AA"、"微信"这种生活词
- "吹吹风"比"轻松逛逛"更生活
- "到时微信约时间" = 真人接洽

### 3.2 邀约生成规则

| 字段 | 取值 | 限制 |
|---|---|---|
| 称呼 | 昵称 or "你" | 不用敬语 |
| 时间 | 具体到分 | 写明"X 点 Y 分" |
| 地点 | 公开场所 | 必须 |
| 预算 | 数值 + AA/请客 | 必写 |
| 节奏 | 用"我"开头 | 不写"我计划" |
| 行动 | 微信/电话 | 不写品牌词 |

### 3.3 模板（不暴露给用户，存 `api/templates/invite.md`）

```
我{weekday}{time}也想去{place}{action}，你{adj}顺路吗？预算 {budget}{aa_or_buy}，到时 {contact} 约时间？
```

**变量**：
- `{weekday}`: 周六/周日
- `{time}`: 14:00
- `{place}`: 大鹏
- `{action}`: 吹吹风 / 逛逛 / 走一走
- `{adj}`: 也 / 刚
- `{budget}`: 180
- `{aa_or_buy}`: 我俩 AA 还行 / 我请
- `{contact}`: 微信 / 群里

## 4. 降权机制（D1）

### 4.1 触发

- 行动卡被用户连续 3 次划走（不点击）
- 用户点过"抑制此类"
- 用户点过"换 3 次搭子"（对场景失去兴趣）

### 4.2 行为

| 累计 | 行为 |
|---|---|
| 第 1 次不点 | 卡片保持不变，触发原因文案软化（去掉"你最近收藏了 X 条"那种直白断言） |
| 第 2 次不点 | 下次标题改为疑问式（"你最近是不是对 XX 不感兴趣？"） |
| 第 3 次不点 | 本场景行动卡冻结 24 小时，Feed 转向下一个高频场景 |

### 4.3 数据结构

```ts
interface DampenState {
  scene: SceneType
  skip_count: number               // 0-3
  last_seen: ISO8601
  last_dampened?: ISO8601          // 最近一次冻结时间
  expiry?: ISO8601                 // 24h 之后
}
```

存储：浏览器 `localStorage`（key: `v2.dampen.<scene>`），后端镜像可选。

## 5. 时间感知（T1）

### 5.1 触发

行动卡标题根据 `Date.now()` 切换：

| 时段 | 美食 | 健身 | 学习 |
|---|---|---|---|
| 11:00-13:00 | "你楼下 5 家适合一人吃的店" | — | — |
| 17:00-20:00 | "今晚 7:30 附近 3 家日料" | "今晚 30 分钟肩背训练" | — |
| 21:00-23:00 | "晚上 11 点附近 3 家烧烤" | — | "今晚 1 小时 AI Agent 学习" |
| 周末 10:00-12:00 | "周末早茶｜罗湖这 3 家" | "周末深圳湾跑步" | "周末 3 小时编程" |

### 5.2 实现

```ts
function timeAwareTitle(scene: SceneType, base: string): string {
  const h = new Date().getHours()
  const isWeekend = [0, 6].includes(new Date().getDay())
  if (scene === 'food') {
    if (h >= 11 && h < 13) return '你楼下 5 家适合一人吃的店'
    if (h >= 17 && h < 20) return '今晚 7:30 附近 3 家日料'
    if (h >= 21) return '晚上 11 点附近 3 家烧烤'
  }
  return base
}
```

## 6. 30 秒问卷（前置条件：刷 10 条才触发）

> 评审指出"首开就弹问卷会穿帮"

### 6.1 触发

- 用户累计看过 ≥ 10 条 feed
- 用户**没有**已存在 persona（localStorage 标记 `v2.persona.exists`）
- 在 Feed 中插入一张"轻提示卡"：`你看过 10 条内容了，要不要告诉 AI 你的偏好？`

### 6.2 内容（7 题，每题 3 选项）

1. 你今天最想做什么？**休息 / 探索 / 完成目标**
2. 你和陌生人最舒服的相处方式？**1v1 私聊 / 多人局 / 不需要人**
3. 你的旅行节奏？**特种兵 / 慢节奏 / 城市漫游**
4. 你的早茶时间？**9 点前 / 9-11 点 / 11 点后**
5. 你的消费偏好？**性价比 / 体验优先 / 颜值优先**
6. 你的周末状态？**经常出逃 / 偶尔出去 / 主要宅家**
7. 你希望 AI 推你做什么？**给方案 / 给搭子 / 两者都要**

### 6.3 输出

写入 `v2.persona.exists=true` + `v2.persona={...}`，后续行动卡根据 persona 排序。

## 7. Twin 成熟度角标（轻量放右上）

### 7.1 三角标

| 等级 | 触发条件 | 角标 |
|---|---|---|
| 初级 Twin | 看过 ≥ 5 条内容 | 🟡 1 格 |
| 进阶 Twin | 看过 ≥ 20 条 + 点过 ≥ 3 张行动卡 | 🟡🟡 2 格 |
| 高级 Twin | 走过 1 次完整协商闭环 | 🟡🟡🟡 3 格 |

### 7.2 卡片显示

卡片右上角小角标 5px 圆点，hover 弹 tooltip 说明"你的 Twin 刚加入 3 天，了解你 20%"。

### 7.3 不作为付费等级

PRD §12 明确**不做会员等级**，只是**画像可信度透明化**。

## 8. 路由与导航

### 8.1 Vue 路由（草案）

```ts
// src/router/index.ts
const routes = [
  { path: '/', redirect: '/feed' },
  { path: '/feed', component: HomeFeed },                  // 黄金顺序 Feed
  { path: '/card/:id', component: ActionCardDetail },      // 卡片详情
  { path: '/negotiate/:cardId', component: AiTwinNegotiation },
  { path: '/invite/:cardId/:candidateId', component: OneClickInvite },
  { path: '/survey', component: OnboardingSurvey },         // 30 秒问卷（前置：刷 10 条）
  { path: '/twin', component: TwinMaturity },               // F8 P2 轻量放卡片右上，单独页可选
  { path: '/archive', component: ActionBox },               // 行动箱 P1（候选 / 暂存）
]
```

### 8.2 状态机入口

- Feed 中点击"行动卡" → `/card/:id`
- 卡片内点"看搭子" → `/card/:id#buddy`
- 选搭子后 → `/negotiate/:cardId`
- 协商完成 → `/invite/:cardId/:candidateId`
