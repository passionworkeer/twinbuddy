# TwinBuddy 安全与边界

> 依据：PRD1 §16 + PRD2 §25 + MING/shield/ethics.md
> 范围：原则 / 必做 / 上线 checklist / 法律风险 / 路演口播

---

## 1. 安全原则（铁律）

| 原则 | 含义 |
|---|---|
| **AI 推进，用户决定** | AI 永远只是"过滤器 + 协商员"，不替用户自动同意线下见面 |
| **公开场所默认** | 所有行动卡首次见面地点默认公开 |
| **不推荐深夜** | 23:00-6:00 不推搭子活动（除非用户主动） |
| **不推荐偏僻** | 山区 / 远郊 / 高风险区域需显著提醒 |
| **双方确认** | 任何推进（路线、邀约、见面）必须双方真人确认 |
| **可拒绝** | 用户可一键拒绝 / 换人 / 取消，无惩罚 |
| **可追溯** | 协商摘要 7 天可查，邀约 30 天可查 |

## 4. 法律风险（评审可能问的刁难问题）

### 4.1 《个人信息保护法》第 24 条

> 通过计算机程序自动分析、评估个人的行为习惯、兴趣爱好或者经济、健康、信用状况等，并进行决策……个人有权要求个人信息处理者予以说明，并有权拒绝。

**TwinBuddy 风险**：
- 我们用行为分析推断"用户可能想做什么"
- 涉及"自动化决策"

**应对**：
- 行动卡标题"基于你最近的 X 个行为" = 显式告知
- 抑制按钮 = 拒绝权
- 用户拒绝 → 不再推本场景

### 4.2 用户生成内容（UGC）

> 用户在 TwinBuddy 写简介、行动卡文案、邀约内容，平台有审核义务

**风险**：
- 色情/暴力/政治敏感 → 平台连带
- 平台收集 UGC 涉及存储义务

**应对**：
- 关键词过滤（demo 可只列规则，不实装）
- 用户举报 → 30 分钟响应（roadmap）
- 不存储"协商摘要"超过 30 天

### 4.3 个人信息画像

> "你最近好像想找个轻松的周末短途旅行" — 这句话本身是画像

**风险**：
- 平台给用户打标签 = 个人信息处理
- 用户对标签有知情权 + 拒绝权

**应对**：
- 卡片底部加 "为什么推荐我" 链接
- 链接页展示触发原因 + 用户最近 5 个行为
- 用户可"修正画像"（标记某条行为"不感兴趣"）

### 4.4 民事责任

> 双方 Twin 协商好周六晚 10 点偏僻咖啡馆见面，出了事谁负责？

**应对（路演说辞）**：
- "我们落地的三道防线：第一，AI 协商结果页明确标注'这是 AI 摘要，最终决定权在双方真人'；第二，高风险场景（深夜、偏僻、单人）强制人工确认才能推进；第三，平台上线前接公安二要素验证 + 行程上报 + 紧急联系人必填 —— 这是 P0 级别，不是上线后再做。"

## 5. 伦理对齐（MING/shield）

依据：`MING/shield/ethics.md`

- **不模拟死者**：不替用户生成已故亲友的 Twin
- **不替未成年人做决定**：18 岁以下不开放搭子推荐
- **不进行情感操控**：不主动推荐"你可能喜欢他"等情感暗示
- **不替用户做道德判断**：不评估"这个搭子够不够好"
- **不替用户拒绝**：协商摘要只能"待确认"，不能"AI 建议你拒绝"

## 7. demo 演示的安全时刻

主 demo 旅行链路里，要展示的安全环节：

1. **行动卡出现** → 显示 "AI 推进，用户决定" 角标
2. **搭子协商结果** → 显示 "这是 AI 摘要" disclaimer
3. **邀约文案** → 显示 "请在公开场所见面"
4. **一键邀约** → 弹"紧急联系人"必填确认（mock 即可）

---

## 8. 评审最爱问的 5 个安全问题

1. **"AI 替用户谈法律风险？"** → 见 §4.4 路演说辞
2. **"未成年人保护？"** → 18 岁以下不开放
3. **"数据卖给第三方？"** → 不卖，行为数据只用于本服务
4. **"黄牛 / 票务合规？"** → 演唱会场景接入大麦/票星球官方 API
5. **"AI 替用户做道德判断？"** → 永远不，AI 只做"事实摘要"
